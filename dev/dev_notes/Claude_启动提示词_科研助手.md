# Claude Code 启动提示词：AI 科研助手 MVP

你现在是我的 AI 科研助手项目的结对开发者。请帮助我用 Python 构建一个面向单用户的科研文献助手 MVP。

## 项目目标
1. 每天定时检查 arXiv。
2. 根据我指定的多个研究主题筛选新论文。
3. 对相关论文生成简版分析，包括：一句话摘要、创新点、疑点/问题、相关性评分、建议动作。
4. 通过飞书把日报或提醒发给我。
5. 我在飞书中的反馈要被系统写入长期记忆。
6. 系统要按主题整理知识，避免所有笔记混在一起。

## 约束条件
- 我会 Python，但不是专业后端工程师，请尽量用简单、稳定、可维护的方案。
- 先做单用户版本。
- 先做飞书，不先做个人微信，但架构要为以后扩展到其他消息平台留接口。
- 模型层必须可替换，后续可能接智谱、千问或其他 API。
- 第一阶段优先保证闭环跑通，不做过度工程化。
- 在解释网络、回调、部署、数据库等概念时，请用通俗语言。

## 你帮助我的方式
- 先设计清晰的项目目录结构。
- 把系统拆成调度、抓取筛选、分析、消息、记忆五个模块。
- 每一步先解释要做什么，再给出代码。
- 代码尽量使用标准库或常见依赖，并写清楚安装方式。
- 帮我生成 `.env.example`、`README`、配置文件示例和最小可运行 demo。
- 当你认为我应该先做一个更小的版本时，请直接建议更小的可运行版本。
- 每次改动请说明：改了哪些文件、为什么这样改、我应该如何测试。

## 我希望你优先给出的内容
1. 第一版项目目录结构。
2. 每个模块的职责说明。
3. 一个最小可运行版本的开发顺序。
4. 第一阶段依赖清单。
5. 第一批要创建的文件及其内容。

## 偏好的工程原则
- 优先清晰，不追求花哨。
- 优先可运行，不追求一次性做全。
- 优先易维护，不追求复杂框架。
- 所有主题、关键词、作者名单、规则都尽量配置化。
- 所有模型调用都通过统一接口封装。
- 所有消息平台都通过适配层封装。
- 所有长期记忆都按主题组织，而不是简单堆聊天记录。

## 如果你认为合适，请先从以下任务开始
请先为我设计一个最小可运行版本：
- 输入：一个主题配置文件
- 过程：抓取最近几天 arXiv -> 规则初筛 -> 调用模型分析 -> 输出 Markdown 日报
- 输出：本地报告文件 + 清晰的 README + 可运行命令

然后再告诉我，下一步如何接入飞书。
